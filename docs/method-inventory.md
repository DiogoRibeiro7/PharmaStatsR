# Export and evidence inventory

Inventory started from `NAMESPACE` on 29 September 2026 and updated as review evidence merges. The 72 `export()` entries are listed exactly once below: 43 statistical methods, six example datasets, 17 utilities, and six optional integrations or templates. All 72 have a source definition and an Rd alias. S3 method registrations for `pharma_t_test` and `pharma_tost` are implementations of those exports, not additional public entries.

This is a **triage ledger**, not a clinical validation certificate or a declaration that an API is stable. “Candidate” means publicly exported but still awaiting an independent method review. “Example” means illustrative data, either hand entered or generated, not clinical observations. “Scope limited” means a utility only does the operation stated; it does not establish regulatory compliance. Issue [#57](https://github.com/DiogoRibeiro7/PharmaStatsR/issues/57) will decide longer-term support and deprecation policy.

**Test key:** [R] is a fixed numerical reference or analytic calculation with boundary checks; [C] is a contract, algorithm behavior, or direct-backend comparison; [S] is a smoke, shape, or class check; [G] covers an optional-backend guard; — means no direct test was located. Each letter links to one representative test file. A test's presence does **not** prove the implementation is correct, and many optional-backend tests skip when the backend is absent from the fast PR job. The site column distinguishes a focused guide from a brief overview or no site mention. The linked R help gives the current full arguments; the short scope text here highlights a constraint to review.

The five resampling, permutation, and trial-simulation exports have a [family review](resampling-review.md) comparing their sampling units, random streams, return values, and evidence. Their individual guides below retain method-specific assumptions.

The short contract column is a prompt for review, not a substitute for a statistical analysis plan. In particular, the following assumptions govern how these families can be interpreted; most wrappers delegate estimation to the named backend and do not verify these assumptions:

| Family and exports | Key interpretation assumptions to review |
| --- | --- |
| `pharma_t_test`, `pharma_tost`, `pharma_anova`, factorial and repeated ANOVA | Sampling and design determine independence and error structure; ordinary ANOVA F tests need a suitable residual and variance model. The repeated helper checks complete two-condition pairs but cannot establish subject independence or distributional assumptions. |
| `pharma_kaplan_meier`, `pharma_survival_fit`, `pharma_parametric_survival`, `pharma_cox_timevarying`, `pharma_landmark_analysis`, `pharma_competing_risks` | Censoring and event coding need study-specific review; Cox hazard ratios assume a proportional-hazards interpretation unless modeled otherwise. Parametric models also rely on the selected event-time family. |
| `pharma_lmm`, `pharma_gee`, `pharma_emax_nlme`, joint and multistate models | Subject or cluster structure, dependence, model specification, and adequate information per parameter require review. A fitted object does not establish those properties. |
| Meta-analysis and network meta-analysis | Effect sizes and sampling errors must be comparable; heterogeneity and, for network comparisons, transitivity and consistency require evaluation. A failed random-effects fit now errors; a separate FE analysis changes the interpretation. |
| `pharma_bayesian_glm`, `pharma_posterior_summary`, `pharma_pp_check`, `pharma_bayes_stopping` | Results are conditional on the likelihood, prior, stopping rule, and, for MCMC, convergence and predictive adequacy. A summary or plot alone is not a diagnostic decision. |
| `pharma_mice_impute`, `pharma_sensitivity_analysis` | Imputation and pooled inference depend on the missingness and imputation-model assumptions; the latter helper does not implement an MNAR scenario analysis. |
| Bootstrap and permutation helpers | Exchangeability or the stated row/cluster resampling unit is part of the design; unrestricted response permutation is unsuitable when that exchangeability fails. |
| `pharma_group_seq`, `pharma_trial_simulate`, `pharma_sample_reestimate` | Planned looks, allocation, event and dropout distributions, and effect-size inputs are study assumptions; simulated operating characteristics need scenario-specific assessment. |
